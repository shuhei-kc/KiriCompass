# KiriCompass — 前例データベース (kifudb)

主にコンピュータ将棋の棋譜 (floodgate / WCSC / 電竜戦 など) から前例データベースを
構築し、局面 (sfen) から候補手と前例対局を高速検索するツール群。
将棋盤GUI (USI対応) にエンジンとして登録すれば、検討中の局面の前例を
リアルタイムに閲覧できる。依存は Python 3.10+ の標準ライブラリのみ。

- [web版KiriCompass](https://478shogi.com/kiricompass/) — 導入不要・ShogiHomeベース
- [導入用記事 (note)](https://note.com/478_shogi/n/n89d157559b65)
- 設計の詳細: [DESIGN.md](DESIGN.md)

## はじめかた

1. このリポジトリを `git clone` する (zipで入手するとmacOSのGatekeeperが
   `.app` をブロックすることがある)。Python 3.10 以上が必要。
2. [配布DB](#配布db) をダウンロードし、`KiriCompass/data/csa.db` に置く。
3. ビューアを起動する — **KiriCompass.app** (macOS) / **KiriCompass.pyw**
   (Windows) をダブルクリック。
4. 将棋盤GUIと連動させる場合は、[USIエンジンを登録](#将棋盤guiとの連動)する。

DBは自分の棋譜からゼロから作ることもできる ([DBの更新](#dbの更新))。

## 配布DB

構築済みのDBを以下で配布している:

https://drive.google.com/drive/u/0/folders/1ZyKwR-fZS2WIG26tmdK1BZLDPB94HcUm

| ファイル | 内容 | サイズ |
| --- | --- | --- |
| **フルDB** `csa.7z` | floodgate 2017年以降 + WCSC 第28回以降 + 電竜戦 全大会 (TSEC含む)。約105.8万局 (2026-07-12時点) | 7z 約4.0GB → 展開後 `csa.db` 約7.2GB |
| **サンプルDB** `csa.db` | floodgate 2026年分 + WCSC36 + 電竜戦第6回本戦。約6.9万局 | 466MB (無圧縮、そのまま使える) |

どちらも最終的に `csa.db` になるので、`KiriCompass/data/` に置くだけで
公開前例DBの既定パスに一致し、起動時のfloodgate更新もそのまま効く
(ビューアの「参照...」で別の場所を選んでもよい)。

## ビューア

SFENを貼り付けて (または将棋盤GUIに追従して) 前例を検索するGUI。

**起動方法**

- macOS: **KiriCompass.app** をダブルクリック。Python 3.10+ を自動で探して記憶する。
- Windows: **KiriCompass.pyw** をダブルクリック。`.pyw` の関連付けが無い等で
  動かない場合は **KiriCompass.bat** (コンソールが一瞬出るが、エラーが読める)。
- CLI: `python3 tools/precedent_gui.py csa.db`

macOS同梱の Python 3.9 は tkinter がクリックを取りこぼす不具合があるため、
起動を拒否する。

**画面の使い方**

- **SFEN欄**: `position sfen ...` / `sfen ...` / `startpos` / 素のSFEN の
  いずれを貼っても検索できる (手数部分は無視)。
- **将棋盤GUIの局面に追従** (既定ON): USIエンジンが書き出す局面に自動で追従する。
- **候補手**: 出現数・勝敗・先手勝率と、指すと既存の前例に合流する手 (合流列)。
  候補手の統計は常にDB全体の合算で、出典フィルタは前例一覧にだけ効く。
- **前例**: 新しい順に表示。出典 (floodgate / WCSC / 電竜戦 TSEC以外・TSEC /
  その他) で絞り込める。選ぶと評価値 (先手視点)・読み筋・URLを表示し、
  ダブルクリックで棋譜ビューアをブラウザで開く。
- **棋譜コピー**: 将棋盤GUIに Ctrl+V / ⌘V でそのまま貼れる形でコピーする
  (元ファイルが残っていればその内容、無ければDBから復元)。
- **対局者名検索**: スペース=AND、大文字の `OR` か `|` =OR、`-語`=除外
  (ANDがORより強い)。例: `dlshogi tanuki OR 水匠 -test`。各語は先手・後手
  どちらかの名前への部分一致で、ASCIIは大文字小文字を区別しない。
  局面を切り替えると自動解除される (適用中はボタン横に表示。検索式は欄に
  残るので、ボタンで再適用できる)。
- **Public / Private / .sfen**: 表示するDBをワンクリックで切り替える
  ([DBの種類](#dbの種類))。
- **▲**: DB行・SFEN行を畳んで画面を広く使う。

## 将棋盤GUIとの連動

```bash
# 登録用ラッパースクリプトを runtime/ に生成し、将棋盤GUIの「エンジン追加」で選択する
python3 tools/usi_engine.py --db csa.db --make-launcher
```

ShogiGUI・将棋所に登録する場合は出力をCP932にする (既定のUTF-8のままだと
日本語のinfo表示が文字化けする)。ランチャー生成時に `--encoding cp932` を
付けるか、GUIのエンジン設定で `OutputEncoding` を `cp932` にする。

- 検討モードで使うと、局面ごとに前例の候補手がmultipvで表示される
  (nodes列=出現局数、読み筋=最頻前例の続き。評価値は意味を持たないので常に0)。
- 閲覧中の局面は `runtime/sync_position.json` に書き出され、ビューアの
  「将棋盤GUIの局面に追従」が自動追従する。エンジン・ビューアはそれぞれ
  単体でも動く (連動は一方向・疎結合)。
- 前例がない局面では `bestmove resign` を返す (定跡専用エンジンとして
  「知識が尽きた」ことを正直に伝える挙動。検討モードではbestmoveは実質無視される)。

ランチャー・syncファイル・GUI設定・ログなどの実行時ファイルはすべて `runtime/` に入る。

## DBの種類

DBは役割で3つに分ける。ビューアの Public / Private / .sfen ボタンで切り替え、
取り込み先は「DB更新...」ウィンドウで設定する。

| DB | 既定パス | 中身 |
| --- | --- | --- |
| **公開前例DB** | `data/csa.db` | floodgate / WCSC / 電竜戦 = 誰でも入手できる棋譜。配布・共有できる状態を保つ |
| **プライベートDB** | `data/private.db` | 個人入手の棋譜 |
| **.sfen DB** | `data/sfen.db` | 連続自己対局 (水匠定跡生成の出力) |

- フォルダ取り込みはファイル名から出典を判定して公開/プライベートに自動で
  振り分ける。判定は大会・サーバーの命名構造まで要求する厳格なもので、
  私的なファイル名が偶然マッチして公開DBへ紛れることはまずない。
- floodgate更新は公開前例DBだけに書く。各取り込み口には混在を防ぐガードが入っている。
- 自己対局の出現数は探索の訪問頻度であって実対局の統計と意味が違うため、
  .sfenは前例DBに混ぜない。
- 取り込み先DBが無ければ確認の上で自動作成されるので、配布DBを「参照...」で
  選ぶ使い方でも、ゼロから作る使い方でも、GUIだけで始められる。

## DBの更新

GUIでは「DB更新...」ウィンドウからすべての取り込みを行う。取り込みは
バックグラウンドで1件ずつ順に実行され、進捗はウィンドウのログ欄と
メイン画面右下に出る。表示中のDBに取り込むと、ビューアは現在の局面を
自動で再検索する。DB更新中にビューアを閉じようとすると確認が出る
(中断してもDBは壊れず、その分が反映されないだけ)。

### floodgate

- ビューアは起動時に1回だけ新規棋譜を確認する (既定ON)。遡り日数はDB内の
  最新対局から自動計算し、最大7日。それを超える空きは自動では取得せず、
  「過去N日分を再走査」を案内する。
- 「今すぐ更新」で任意のタイミングでも取得できる。配布DBを使う場合はこれで十分。
- 参照するのは終局棋譜の日別アーカイブのみ (ライブページは叩かない)。
  ダウンロードした棋譜は取り込み後に削除され、未終局のものだけ
  `data/floodgate/` に一時保持されて次回再確認される。0手で不成立だった
  対局は取り込み台帳に記録だけ残して削除し、以後ダウンロードしない。

### 棋譜フォルダ (CSA / KIF)

GUIの「フォルダを選択して振り分け取り込み...」で、フォルダ内 (サブフォルダ含む) の
`.csa` / `.kif` / `.kifu` を増分登録する。同じフォルダに再実行しても安全。

- 未終局の棋譜は取り込まれず、ファイル更新後の再実行で自動的に再チェックされる。
  0手のファイルは対局不成立として別カウントされる。
- 読めない・壊れた棋譜は1ファイル単位でスキップして続行する (その1件だけ
  ロールバックされ、DBに中途半端な行は残らない)。ログには読めなかった
  ファイル名が出て、詳細は `runtime/kiricompass.log` に残る。
- プライベートDBの重複排除は指し手内容ベース — 別フォルダの同名ファイルが
  別対局でも正しく両方登録される。
- 大会棋譜などは、できるだけ出典ごとにまとめて登録するのがおすすめ
  ([メモ](#メモ))。

CLIでは:

```bash
python3 tools/build_db.py csa.db /path/to/kifu_folder --log build.log
```

### .sfen 連続対局

「DB更新...」ウィンドウの .sfen セクションから .sfen DB に取り込む。
1ファイル = 1バッチ、1行 = 1局。

```text
startpos moves 7g7f 3c3d ... resign
sfen <局面> moves 7g7f ... rep_draw
position startpos moves 2g2f ... max_moves
```

| 終局トークン | 意味 | 集計 |
| --- | --- | --- |
| `resign` | 投了 | 終局時の手番側の負け (任意局面からの対局は初期手番も反映) |
| `rep_draw` | 千日手 | 引き分け |
| `max_moves` | 最大手数 | 引き分け |

- **追加**: 新規バッチは取り込み前にプレビュー (局数・課題局面・読めない行の例)
  が出て、ラベル (対局者名として表示) と日付を指定できる。複数ファイルを
  選んだときは、残りを確認なしで取り込むこともできる。
- **課題局面**: バッチの全局に共通する手順は「課題局面」という擬似対局として
  1回だけ登録され、どこを課題局面にしたか後から見返せる。
- **追記**: 同名ファイルの追記は自動で差分だけ取り込む。生成中のファイルを
  取り込んでもよい — 改行で終わっていない書きかけの最終行は次回に回すので、
  書き上がった後の取り込みは通常の追記になる。「追記を取り込み (全バッチ)」は
  1ヶ月以上前の日付のバッチを対象外にするので、古いファイルは
  「.sfenファイルを追加...」から選び直す。
- **競合**: 既読部分が書き換わったファイルは競合として扱われる。編集を反映する
  には、バッチを削除してから追加し直す。
- **削除**: バッチ単位で完全に削除できる (複数選択可。.sfenファイル自体は消えない)。
- **読めない行**: 持駒のない駒打ちなど盤面と矛盾する手順や形式違いの行は、
  行単位で警告してスキップする。ログには先頭10行だけ出し、全件は
  `runtime/kiricompass.log` に残る。BOM付きのファイルも読める。
- **旧版で登録したバッチ**: 同じファイルを再取り込みすると初回だけ再構築され、
  以前スキップされた `max_moves` の対局、BOM付きの先頭行や `position ...`
  形式の行、後手番開始の勝敗も反映される。

## コマンドライン

GUIを使わずに、同じ処理をCLIから実行できる。

| コマンド | 用途 |
| --- | --- |
| `tools/build_db.py <db> <folder>` | 棋譜フォルダからDBを作成・増分更新 (`--log` `--cache-mb` `--pv-max-moves`) |
| `tools/update_floodgate.py <db>` | floodgateの新規棋譜を1回取り込む (`--days` `--jitter` `--log`) |
| `tools/usi_engine.py --db <db>` | USIダミーエンジン (`--make-launcher` `--encoding` `--multipv`) |
| `tools/precedent_gui.py [db]` | ビューア |
| `tools/download_wcsc.py <回>...` | WCSC / WCSO の棋譜を配信元のファイル名のまま保存 |
| `tools/download_denryusen.py [大会ID]...` | 電竜戦の棋譜を `data/denryusen/` に保存 |

**DB名の解決規則 (全ツール共通):** `csa.db` のようにディレクトリなしで
指定したDB名は、どこから実行しても常に `KiriCompass/data/` (リポジトリ
直下の data フォルダ) を指す。別の場所のDBを使う場合は絶対パスか、
`./csa.db`・`path/to/csa.db` のようにディレクトリ付きで指定する。

## メモ

- **大会棋譜などの追加登録は、できるだけ出典ごとにまとめて行うのがおすすめ。**
  出典フィルタは「出典→game_idの連続区間」の表で高速化されており、取り込みの
  たびに区間が1つ増える。細切れに交互登録しても動作は正しいまま
  (区間が増えるだけで自動追従する) が、まとめて登録するほど表が小さく保たれる。
- TSEC等のbuoy対局は、サーバーが事前に並べた指定手順を対局本体から分離し、
  「指定局面」という擬似対局として1回だけ索引する (.sfenの課題局面と同じ)。
  指定局面までの手は対局エンジンが選んだ手ではないため統計に数えず、
  出現は擬似対局の1回分だけになる。前例一覧では終局理由「指定局面」の行
  として見え、そこから共通手順の棋譜も辿れる。
- 読み筋を保存したくない場合は `build_db.py --pv-max-moves 0`。
- 検索はプロセス内で接続を使い回してキャッシュを温存する (エンジン・GUIとも対応済み)。
  外部SSD上のDBで初回や放置後のアクセスだけ遅いのはドライブのスリープ/コールド
  リードによるもので、2回目以降は速くなる。
- DB構築はメモリを最大でも数百MB程度しか使わない (SQLiteのページキャッシュ256MB
  + 作業用セット)。マシンのメモリ使用量が増えて見えるのは主にOSのファイル
  キャッシュで、問題ない。大きなDBへの追記が遅いときは、空きメモリに応じて
  `build_db.py --cache-mb 2048` のようにキャッシュを増やすと速くなる
  (既定は小さめに固定してあり、増やすかどうかは利用者の判断に委ねる)。
- 取り込みで何が起きたかは `runtime/kiricompass.log` に残る (GUIのログ窓を
  閉じても・途中で落ちても追える)。CLIの `build_db.py` は `--log` で同じ内容を出せる。
